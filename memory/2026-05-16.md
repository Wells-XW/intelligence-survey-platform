### 选型

走「WebSocket 增量广播 + 题目级软锁 + 乐观锁兜底」而非完整 CRDT。理由：
- 学术问卷协作模式与 Google Docs 文本流不同，同时编辑同一题的概率低
- 现有乐观锁（`expected_version` + 409 + ConflictDialog）已经能处理「两人同时保存」
- 软锁 + 广播能在 5% 复杂度下拿到 80% 价值，不破坏现有 SurveyJS + TanStack Query 流水线
- CRDT 留作 T13.4 增量演进

### 与现有乐观锁的协同

软锁是 UX 提示，不是权威性。两人同时保存仍由乐观锁裁决：
1. A 聚焦 Q1，B 看到「A 正在编辑」，但 B 仍可编辑（软锁）
2. A 先 ctrl+S → server 接受，version++ → 广播 `survey.saved`
3. B 没看到广播就保存 → 409 → ConflictDialog 弹起
4. B 看到广播 → 自动拉新 → 基于最新 version 编辑
